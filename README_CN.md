# 群策 Council · 本地 AI 圆桌 MVP

一个在自己电脑上运行的 AI 群聊工作台。把多个官方网页账号的入口放进同一个讨论室：分配角色、选择回答成员、保留本地历史。**无需 API Key，也不是免费调用模型的后门。** 各服务的账号、额度、地区限制及服务条款仍然适用。

## 此版本真实能力边界

- **DEMO**：默认模式，确定性本地模板并发回复，所有回复明确标记演示。不连接任何 AI，不代表已登录或真实模型结果。浏览器预览只支持此模式。
- **DeepSeek、豆包、Kimi 文字收发**：通过原网页输入框提交文字，读取助手回复并检测页面生成结束。2026-10-26 已用本机登录账号验证三平台群聊收发、新会话建立和重启续聊；Kimi 使用“快速”模式，K3.1 Pro 曾提示高峰期优先队列。网站改版、验证码、登录失效和服务额度仍可能影响使用。完成判断基于页面状态，不是服务端协议确认。
- **通义千问、Gemini**：独立账号分区和原网页窗口已实现；群聊自动收发尚未实现，请在原网页操作。
- 角色是一条普通首条用户消息，**不是模型真正的 system 指令**；修改角色不能改写已初始化的网页对话。请在原站新建聊天并重置绑定再使用新角色。
- @名称 或成员选择控制路由；未指定时向已启用成员广播。各成员的错误互相独立。发送时自动恢复当前群聊的原网页会话，打开后自动检测输入框；已有草稿不会被覆盖。
- 文本、状态、下载文件卡片；文件上传、多模态、生成附件等优先回到原站。原站下载经原账号会话触发保存对话框，只显示状态，不自动打开文件。
- SQLite 工作线程保存群聊、角色、消息、设置和初始化状态。崩溃/重启后的进行中任务标为“不确定”，**不会自动重发**。取消是停止本地接收并尝试原站停止按钮，不能保证原站服务已经停止。

## 启动与构建

建议 Node.js 22.12+ / 24 LTS，npm 10+。首次安装需要网络及原生模块编译工具；平台原生依赖可能需要 C/C++、Python。

```bash
npm ci
npm test
npm run typecheck
npm run dev
```

macOS / Windows 的完整环境准备、便捷启动、原生模块重建与无签名打包见 [DEVELOPMENT.md](DEVELOPMENT.md)。

独立浏览器演示（同一套 Vue 界面和 bridge 接口，localStorage 仅保存 DEMO 数据）：

```bash
npm run preview:web -- --port 5173
# 或构建后用任意本地静态服务器打开 web-demo
npm run build:web
# 生成可以直接打开的单文件演示（无联网、无真实账号）
npm run build:offline
```

桌面打包：

```bash
npm run dist:linux  # Linux x64 tar.gz；需要桌面会话才能运行
npm run dist:mac    # macOS 本机无签名 DMG
npm run dist:win    # Windows 本机无签名 NSIS 安装包
```

本机实际验证记录见 LOCAL_VALIDATION.md；Windows 尚未实机验证。不要通过关闭 Electron sandbox、webSecurity 或系统安全保护来规避运行问题。

也可直接打开交付的 `Council-DEMO-离线预览.html`（约 1 MB）。它只运行明确标记的模拟回复，未完成当前环境的图形交互验收。

## 安全与隐私

- 应用不收集/记录密码、不读取/导出 Cookie、令牌或浏览器认证数据库。用户在可见的官方网页手动登录。
- Electron 自身将官方网页账号会话保存在本机 `userData/Partitions`；这是持久登录所必需的浏览器数据，**不等于应用没有本地登录数据**。每个平台使用独立 `persist:council-{provider}` 分区，同平台不同讨论室共享账号但使用不同网页视图。
- 远程视图启用 sandbox、contextIsolation，禁用 nodeIntegration；无远程 preload，无 CSP 删除，无机器人/验证码绕过。只允许对应服务 HTTPS 白名单导航；第三方 OAuth 可能被限制，MVP 不保证所有登录方式可用。
- 渲染界面只有经过发送方、主 frame、URL 和 Zod schema 校验的窄 IPC。消息作为文本展示，不执行模型 HTML。
- SQLite 是本地**未加密**文件；对话可能含敏感信息，请保护操作系统账号及磁盘。应用没有云同步。发送时用户输入会传给所选官方服务；可选“附带群聊上下文”会把同组历史分享给所选服务，请审慎开启。
- 使用网页自动化前请自行确认各服务条款；不承诺长期可用，不突破限额，不自动重试提交。

## 首次桌面试用

1. 先保持 DEMO，创建讨论室、编辑角色；输入问题，观察并发状态。
2. 用 `@Kimi`（或成员选择）只让一位回复；停止后再发，切换讨论室确认不串消息。
3. 退出并重开，确认历史/成员/设置保留。
4. 在设置切换真实网页模式。启用 DeepSeek、豆包、Kimi，在各自原网页中手动登录，等待右侧显示“网页就绪”。Kimi 可在原网页选择可用的模型；App 不会自动切换模型。
5. 发送无敏感信息的短问题，检查三平台回传、@ 单成员、关闭原网页后恢复续聊。若出现限流或“不确定”，先在原网页核对，不反复重发。
6. 在生成时取消、刷新原网页或退出应用，再重启；确认“不确定”阻止自动续发。先核对实际发送结果，再手动确认或新建原站聊天后重置。
7. 通义和 Gemini 仅验证原网页入口及“不支持自动收发”的提示。
8. 在原站产生文件后手动下载，确认保存对话框、状态卡片和无自动打开行为。

## 项目结构

- `src/main`：Electron 主进程、SQLite worker、原站窗口和三平台 DOM 文字适配器
- `src/preload`：窄 IPC bridge
- `src/shared`：数据模型、路由、恢复、角色 bootstrap 与固定 DEMO 模板
- `src/renderer`：Vue 3 / Pinia / Naive UI / vue-advanced-chat 实际聊天界面
- `tests`：路由、恢复、不重复提交、取消、并发等自动化测试

具体已执行验证见 `QA_REPORT.md`。开源许可证见 `LICENSE`、`THIRD_PARTY_NOTICES.md`。
